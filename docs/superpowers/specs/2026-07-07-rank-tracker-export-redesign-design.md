# 순위 추적 엑셀 내보내기 개선 설계 스펙

**작성일:** 2026-07-07
**범위:** 순위 추적(`RankTrackerPage`) 엑셀 내보내기(`handleExport` / `buildHeatmapSheet`) 개편
**적용 대상:** 순위 추적 기능을 쓰는 모든 사용자 (기존 프리미엄 게이트 유지, 로직 변경 없음)

---

## 1. 배경 및 문제

키워드/블로그 등록이 계속 늘어나면서(현재 ~100건, 월 200건대로 증가 추세) 엑셀 내보내기 결과의 한 시트 안 행 수가 계속 늘어난다. 그룹별로 시트는 이미 나뉘어 있지만, 시트 하나 안에서도:

1. 행이 많아지면 스크롤할 때 헤더가 사라져 어떤 열인지 다시 위로 올라가 확인해야 함
2. 특정 키워드·블로그만 골라보거나 필터링할 방법이 없음
3. 정렬이 키워드 가나다순이라 "중요도(검색량)가 높은 키워드부터" 훑어보기 어려움
4. "그룹" 열이 시트마다 반복되는데, 시트가 이미 그룹 단위라 정보가 중복됨
5. 순위 색상 팔레트가 원색적이고(구글 머티리얼 색 그대로 사용), 셀 테두리가 엑셀 기본 격자선에만 의존해 인쇄/타 프로그램에서 열면 구분선이 흐려짐

히트맵 형태(키워드×블로그를 행, 날짜를 열로 하는 표) 자체는 유지하되, 위 문제들을 해결한다.

---

## 2. 라이브러리 교체: `xlsx-js-style` → `exceljs`

현재 쓰는 `xlsx-js-style`(SheetJS Community Edition 기반)은 셀 스타일·열너비·자동필터(`!autofilter`)는 지원하지만, **틀 고정(freeze panes)은 쓰기 자체가 불가능**하다(SheetJS CE의 알려진 한계 — 읽기는 되지만 쓰기는 Pro 버전 전용). 틀 고정 없이는 행이 많아졌을 때 헤더/키워드 열이 스크롤에 밀려 사라지는 문제를 해결할 수 없다.

`exceljs`는 셀 스타일, 열너비, 자동필터, 틀 고정(`worksheet.views`)을 모두 정식 API로 지원하며 활발히 유지보수되는 라이브러리다. 이번 개편에서 내보내기 관련 코드를 `exceljs` 기반으로 재작성한다.

- `client/src/pages/RankTrackerPage.jsx`의 `import * as XLSX from 'xlsx-js-style'`를 제거하고, `handleExport` 함수 안에서 `const ExcelJS = await import('exceljs')`로 **동적 import** — 내보내기 버튼을 누르는 시점에만 로드되어 초기 번들 크기에 영향 없음.
- `buildHeatmapSheet(rows)`는 `ExcelJS.Workbook` / `worksheet.addRow` / `cell.style` 기반으로 다시 작성.
- 워크북 조립(`XLSX.utils.book_new`/`book_append_sheet`) → `new ExcelJS.Workbook()` + `workbook.addWorksheet(name)`.
- 파일 다운로드(`XLSX.writeFile`) → `await workbook.xlsx.writeBuffer()`로 `ArrayBuffer`를 얻은 뒤 `Blob` + `<a download>` 클릭으로 저장(브라우저에 이미 있는 표준 패턴, 추가 의존성 불필요).
- `client/package.json`에 `exceljs` 추가. `xlsx-js-style`는 `BulkImportModal.jsx`(업로드된 엑셀 파일 파싱)와 `App.jsx`(키워드 분석 결과 내보내기)에서 계속 쓰이므로 **제거하지 않는다** — 이번 개편은 순위 추적 내보내기 경로에만 `exceljs`를 도입하는 것이고, 다른 두 곳은 손대지 않는다.

## 3. 정렬 순서 변경

기존: 키워드 가나다순 → blogId 가나다순.

변경: **월간 검색량 내림차순(1순위) → 등록일(포스팅 발행일 또는 트래커 등록일) 오래된순(2순위)**.

- 검색량이 `null`(미조회)인 키워드는 맨 뒤로 보낸다.
- 같은 키워드의 여러 블로그 행은 검색량이 동일하므로 자연히 인접하게 묶여 보인다. 그 안에서는 등록일 오래된순으로 2차 정렬.
- 정렬은 `buildHeatmapSheet` 내부, 기존 `dataRows.sort(...)` 부분만 교체하면 되고 데이터 구조 변경은 없다.

## 4. 그룹 열 제거 + 제목 행 추가

- 헤더에서 "그룹" 열을 제거한다(시트가 이미 그룹 단위로 나뉘어 있어 열 자체가 중복 정보). 나머지 열이 한 칸씩 당겨진다: `등록일 | 키워드 | 월간 검색량 | 블로그 | 통검 노출 | (날짜...)`.
- 대신 표 맨 위에 **제목 행**을 추가해 그룹명을 표시한다: `그룹: {groupName}` 텍스트를 데이터 열 전체 너비만큼 병합(merge)하고, 헤더 행과는 톤이 다른 배경색(`#2A3550`, 헤더의 `#1C2333`보다 밝은 네이비)에 13pt bold 흰 글씨로 표시.
- 제목 행이 추가되면서 이후 모든 행 좌표(헤더 행, 데이터 행 시작, 범례 시작 행 등)가 1행씩 밀린다 — 기존 `legendStartRow`/`integratedLegendStartRow` 계산 로직도 그만큼 보정.

---

## 5. 틀 고정(freeze panes) + 자동필터

- **틀 고정**: 제목 행 + 헤더 행(총 2행)과, 왼쪽 정보열(등록일·키워드·월간 검색량·블로그·통검 노출, 그룹 제거 후 5개 열)을 고정한다.
  - `worksheet.views = [{ state: 'frozen', xSplit: 5, ySplit: 2 }]`
  - 스크롤을 오른쪽(날짜 열)이나 아래쪽(행)으로 아무리 내려도 제목·헤더·키워드 정보는 항상 화면에 남는다.
- **자동필터**: 헤더 행(제목 행 제외, 실제 컬럼명이 있는 행) 전체 범위에 엑셀 자동필터 드롭다운을 추가한다.
  - `worksheet.autoFilter = { from: { row: 2, column: 1 }, to: { row: 2, column: totalCols } }`
  - 범례 영역(표 아래 별도 블록)은 자동필터 범위에서 제외 — 필터 대상은 실제 데이터 표 범위로 한정.

## 6. 비주얼 리디자인

**순위 색상 팔레트**: 기존 구글 머티리얼 색상(`1E8E3E`, `FBBC04`, `F28B82` 등)을 채도를 낮춘 초록→황→빨강 그라데이션으로 교체:

| 구간 | 배경색 | 글자색 |
|---|---|---|
| 1위 | `#2E7D32` | `#FFFFFF` |
| 2위 | `#43A047` | `#FFFFFF` |
| 3위 | `#7CB342` | `#1A3C1A` |
| 5위 | `#F4B942` | `#5C4400` |
| 7위 | `#EF8354` | `#5C2A00` |
| 10위(6~10) | `#D9534F` | `#FFFFFF` |
| 미노출 | `#EEEEEE` | `#9E9E9E` |
| 조회 실패 | `#BCAAA4` (채도 낮춘 회갈색, 순위 팔레트와 구분) | `#3E2723` |

통검노출 O/X 색상(`#1A73E8` / `#B3C6E8`)은 순위 팔레트와 겹치지 않는 블루 계열을 유지하되 톤만 다듬는다(정확한 값은 구현 중 실제 파일 눈으로 보고 미세 조정 가능).

**테두리/구분선**: 모든 데이터 셀에 옅은 회색(`#D9D9D9`) 얇은 테두리를 명시적으로 지정해 인쇄·타 프로그램에서도 격자가 유지되게 한다. 헤더 행 아래에는 좀 더 굵은 구분선(`#1C2333`, medium)을 넣어 제목/헤더/본문 영역을 시각적으로 분리한다.

**폰트**: 제목 행 13pt bold, 헤더 행 11pt bold, 본문 10~11pt — 폰트 패밀리를 명시적으로 `맑은 고딕`으로 지정해 어떤 환경에서 열어도 동일한 느낌을 준다(기존엔 미지정이라 엑셀 기본 Calibri로 표시됨).

## 7. 유지되는 것

- 히트맵 셀 값 로직(순위 있으면 숫자, 없으면 X, 조회실패면 "실패" 문자열) 그대로.
- 범례(순위 컬러 / 통검노출 컬러 / 발행일 폴백 안내 문구) 구성 그대로, 좌표만 제목 행 추가분만큼 보정.
- 그룹별 시트 분리, 시트명 중복 처리(`(2)`, `(3)` 등), 파일명 규칙(`순위기록_{그룹}_{날짜}.xlsx`) 그대로.
- 열너비 자동계산(`autoColWidth`/`displayWidth`) 로직 그대로, exceljs API에 맞게 적용 방식만 이식.
- 서버 쪽 `exportSnapshots`(데이터 조회/필터링)는 변경 없음 — 이번 개편은 프론트엔드 시트 생성 로직에 한정.

## 8. 리스크 및 검증 방법

- 라이브러리를 통째로 교체하므로 회귀 위험이 있다. 이 프로젝트엔 내보내기 결과물을 검증하는 프론트 자동 테스트가 없어(엑셀 파일 자체를 assert하는 테스트는 실익이 낮음), **수동 검증**이 필요하다:
  1. 로컬에서 여러 그룹·여러 키워드·여러 블로그·여러 날짜 데이터가 있는 상태로 내보내기 실행
  2. 생성된 `.xlsx`를 실제로 열어 확인: 제목 행(그룹명), 헤더 고정, 자동필터 동작, 정렬 순서(검색량 desc → 등록일 asc), 색상 팔레트, 테두리, 열너비, 파일명, 시트명 중복 처리, 조회실패/미노출 셀 표시, 범례 위치가 모두 의도대로 나오는지
  3. 그룹이 없는(`없음`) 항목, 검색량 미조회(`null`) 항목, 발행일 폴백(`*`) 항목 등 경계 케이스도 최소 1건씩 포함해 확인
- 두 라이브러리(`xlsx-js-style`, `exceljs`)가 당분간 나란히 의존성에 남는다. `xlsx-js-style`는 `BulkImportModal.jsx`/`App.jsx`에서 기존처럼 상단 정적 import로 남아(이번 개편 범위 밖) 번들 영향에 변화 없고, 새로 추가되는 `exceljs`만 내보내기 클릭 시점의 동적 import라 초기 로딩에는 영향이 없다.
