# 인앱 사용 가이드 페이지 설계 스펙

**작성일:** 2026-07-10
**범위:** 네비게이션의 "사용 가이드" 버튼이 열던 노션 링크를 걷어내고, 앱 안에 자체 가이드 페이지를 새로 만든다.
**적용 대상:** 로그인 여부와 무관하게 누구나 접근 가능.

---

## 1. 배경

지금까지 "사용 가이드" 버튼은 외부 노션 페이지(`NOTION_GUIDE_URL`)를 새 탭으로 열었다. 노션 페이지는 앱 디자인과 톤이 다르고, 실제로 내용을 확인해보니 접근이 막혀있거나 비어있는 상태였다. 이 앱에 이미 있는 페이지 전환 패턴(`activeTab` 기반, `PricingPage`/`DashboardPage`처럼 자체 페이지 컴포넌트)을 그대로 따라 인앱 가이드 페이지를 만든다.

---

## 2. 아키텍처

- **신규 페이지**: `client/src/pages/GuidePage.jsx` — 왼쪽 사이드바(카테고리·항목 목차) + 오른쪽 콘텐츠 패널(선택한 항목의 단계별 설명) 2단 레이아웃. 항목 클릭 시 스크롤이 아니라 오른쪽 패널 내용 자체가 바뀌는 방식(내부 `useState`로 선택된 항목 관리).
- **신규 콘텐츠 데이터**: `client/src/data/guideContent.js` — 가이드 텍스트를 컴포넌트 코드와 분리해서 관리(3절 참고). `GuidePage.jsx`는 이 데이터를 순회하며 사이드바/콘텐츠를 렌더링하는 프레젠테이션 컴포넌트로만 존재.
- **네비게이션 연결**:
  - `client/src/App.jsx`: `activeTab === 'guide'`일 때 `GuidePage`를 렌더링하는 분기 추가(기존 `pricing`/`dashboard` 분기와 동일한 위치·패턴).
  - `client/src/components/Navbar.jsx`: "사용 가이드" 버튼의 `onClick`을 `() => window.open(NOTION_GUIDE_URL, ...)`에서 `() => onSwitchTab('guide')`로 교체. `NOTION_GUIDE_URL` 상수와 그 값은 더 이상 쓰이지 않으므로 제거.
- **접근 제어**: 로그인/프리미엄 게이트 없음 — `pricing`과 동일하게 완전 공개.

---

## 3. 콘텐츠 데이터 형태

`guideContent.js`는 카테고리 배열을 export한다:

```js
export const GUIDE_CATEGORIES = [
  {
    id: 'getting-started',
    label: '시작하기',
    items: [
      {
        id: 'signup',
        title: '회원가입과 로그인',
        summary: '한 줄 요약',
        steps: ['1단계 설명', '2단계 설명', ...],
        tip: '선택적 보충 설명(팁/주의사항), 없으면 생략 가능',
      },
      // ...
    ],
  },
  // ...
];
```

- `steps`는 문자열 배열(각 원소가 번호 매겨진 한 단계). 콘텐츠 패널은 `<ol>`로 렌더링.
- `tip`은 선택 필드 — 있으면 콘텐츠 하단에 강조 박스로 표시.
- 이 배열 하나로 사이드바 목차와 콘텐츠 패널을 모두 생성한다(목차를 따로 하드코딩하지 않음).

---

## 4. 목차 구성 (전체 카테고리·항목)

실제 코드베이스 동작을 기준으로 조사한 내용이며(리서치 결과 반영), 각 항목은 "실제로 어디를 클릭하고 무엇을 입력하는지" 단계별로 서술한다.

**1. 시작하기**
- 회원가입과 로그인 (구글/이메일, 7일 무료체험 자동 적용)
- 베이직 vs 프리미엄 차이 (기능·한도 비교)

**2. 키워드 분석**
- 키워드 검색하는 법 (검색창, 비로그인 4회 제한)
- 필터로 키워드 좁히기 (경쟁도/추천 상태/최소 검색량/낮은 연관도·과포화 제외 토글)
- 결과 해석하기 (키워드 인사이트, 요약 카드, 효율 점수·추천 액션 의미)
- 정렬과 컬럼 커스터마이즈
- 엑셀로 다운로드하기

**3. 블로그 분석**
- 블로그 구조 분석 (키워드로 상위 노출 게시물 패턴 분석)
- 블로그 진단 (URL로 내 블로그 점수·등급 확인)

**4. 순위 추적**
- 키워드·블로그 등록하기 (개별 등록 / 대량 등록)
- 그룹으로 관리하기
- 순위 갱신하기 (개별/전체 갱신)
- 정렬·검색·즐겨찾기
- 상세 보기 (차트, 캘린더)
- Slack 알림 설정
- 리포트 공유 링크 만들기
- 엑셀로 내보내기

**5. 대시보드**
- 대시보드에서 한눈에 보기 (통계 카드, 최근 변동, 최근 검색)

**6. 요금제·결제**
- 플랜 비교하고 업그레이드하기
- 결제 방법 (Groble)

총 6개 카테고리, 20개 항목. 각 항목은 실제 UI 라벨/버튼 이름을 그대로 인용해 사용자가 화면과 1:1로 대조할 수 있게 쓴다(예: "'대량 등록' 버튼을 클릭하면...").

---

## 5. 시각 디자인

새 스타일을 발명하지 않고 기존 `.mac-card`/`.mac-btn*` 등을 재사용한다.

- **레이아웃**: `max-width` 컨테이너 안에 `grid-template-columns: 240px 1fr` (데스크톱). 사이드바는 `position: sticky`로 스크롤해도 고정.
- **사이드바**: 카테고리 라벨(굵게, 소제목) 아래 항목 리스트. 선택된 항목은 `var(--accent)` 색상 + 왼쪽 강조선으로 구분(다른 페이지의 활성 탭 표시 패턴과 동일).
- **콘텐츠 패널**: `.mac-card` 안에 제목 + `summary` + 번호 매긴 단계 목록(`<ol>`, 각 단계 카드형이 아니라 심플한 리스트) + 있으면 `tip` 강조 박스(예: `background: rgba(10,132,255,0.08)`, 왼쪽 강조선).
- **모바일**: 사이드바는 상단에 가로 스크롤 pill 목록으로 축소(기존 반응형 패턴 재사용).

---

## 6. 유지되는 것 / 변경 없는 것

- 노션 "업데이트 로그"(`NOTION_UPDATE_URL`)는 이번 변경과 무관 — 그대로 둔다.
- 다른 페이지/기능 로직은 전혀 건드리지 않는다. 순수 신규 페이지 추가 + 네비게이션 버튼 1개 동작 변경.

---

## 7. 검증 방법

- 프론트 자동 테스트가 없는 프로젝트라 `npm run build` 통과 + 수동 확인(가이드 페이지 진입, 사이드바 항목 클릭 시 콘텐츠 전환, 비로그인 상태에서도 접근되는지, 다른 탭에서 "사용 가이드" 클릭 시 정상 이동하는지)으로 검증한다.
